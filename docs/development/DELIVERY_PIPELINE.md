# Параллельная работа и доставка

Решение пользователя, 11 октября 2026: процесс перенесён из The Village и подогнан под веб-игру без сборки. Каждый чат работает в своём git worktree, общим остаётся только короткий шаг доставки. Скрипт: `tools/pipeline.py`.

## Ветки: `dev` наша, `main` общая

```
чаты (work/<чат>) --deliver-->  dev  --publish, по слову пользователя-->  main
                                 ^                                         |
                                 +------- merge-main + deliver <-----------+
```

- `dev` — наша ветка: все `deliver` идут в неё, версии считаются в ней. Основная папка — это `dev`.
- `main` — общая (релизная). Наше попадает туда только через `python3 tools/pipeline.py publish`, когда пользователь скажет. Порядок такой:
  - `publish` проверяет, что `main` влита в `dev`, а основная папка стоит на текущем `dev`;
  - гоняет `--probe` (`{main}` — путь основной папки);
  - открывает PR `dev → main` со списком доставок (`--notes` — человеческое саммари сверху), сливает его и ставит метку `v<версия>`;
  - подтягивает `dev` к коммиту слияния.
  - `--dry-run` только печатает текст PR.
- Чужая работа из `main`: в своей папке `python3 tools/pipeline.py merge-main`, затем `deliver` с напечатанным `--message`.
- **Pre-push hook** ставит сам `pipeline.py` в общие hooks репозитория, при любом запуске. Он останавливает:
  - push в `main`;
  - push в `dev`, который не продолжает `origin/dev` (то есть `--force`);
  - удаление `dev`.

| Папка | Ветка | Что это |
|---|---|---|
| `very-big-adventure-main` | `dev` | **основная**: зеркало `origin/dev`, игра пользователя на :5173. Никто не правит |
| `very-big-adventure-<имя>` | `work/<имя>` | папка чата: `python3 tools/pipeline.py new <имя>` |
| `very-big-adventure` | — (`main` без ветки) | хранилище git всех папок; никто не правит и не играет. Работа RND — в теге `archive/rnd-2026-10-11` |

- Основная папка — та, где выписана `dev`. Скрипт запоминает её в `.git/vba-pipeline/main-folder`, поэтому после `rollback` (detached HEAD) она остаётся основной.
- Свою папку можно держать сколько угодно и переиспользовать: после доставки ветка уже стоит на новом `dev`. Удалить: `git worktree remove ../very-big-adventure-<имя>`.

## Доставка

Условия: запуск из своей папки (не из основной), всё закоммичено, `git status` чистый.

```sh
python3 tools/pipeline.py deliver --task dice-fix \
  --probe "python3 tools/probe.py test tests/dice.test.mjs --out Logs/probes/{run}"
```

Что делает скрипт:

0. **Очередь.** Игровые доставки идут по одной, `--no-app` очередь не ждёт.
1. **Сжатие.** `git fetch` и сжатие ветки в один коммит поверх свежего `origin/dev` (`git merge-tree`, рабочие файлы не трогаются до успеха). Строка версии ветки сначала возвращается к общей базе, поэтому версия никогда не даёт конфликта.
2. **Версия** = максимум из `origin/dev` и `origin/main` + 1. Пишется в `src/version.js` (`GAME_VERSION`) и в заголовок коммита: «Заголовок (0.1.7)». Первая игровая доставка создаёт файл с `0.1.1`.
3. **Проверка вместо сборки:** `node --check` каждого изменённого скрипта, секунды. Если задет код или карты — весь набор `node --test tests/*.test.*js` (доли секунды, с 18 октября 2026: 0.1.44 оставил красными 6 тестов чужого файла на три доставки). Красный тест в любом файле — ничего не заливается.
4. **Пробы** по очереди в своей папке. Подстановки:
   - `{run}` — уникальная метка пробы (папку вывода давать как `--out Logs/probes/{run}`);
   - `{run1}`, `{run2}` — метки первой, второй пробы этой попытки;
   - `{version}` — версия.

   Любая ошибка останавливает доставку: ничего не залито.
5. **Push в `dev`.** Если `dev` за это время ушёл вперёд только в `tools/`, `docs/`, `tests/`, коммит кладётся поверх без повторных проверок. Если пришли игровые файлы, попытка повторяется.
6. **Основная папка** подтягивается `git merge --ff-only`. Её прошлый коммит — бэкап, он записан в `.git/vba-pipeline/installed.json` как `previous`. Копий файлов нет, поэтому чистить нечего.
7. **Сервер :5173.**
   - Статику сервер читает с диска на каждый запрос, поэтому перезапуск нужен, только если менялся `server.js`.
   - Если игра не открыта (нет соединений с :5173), скрипт перезапускает сервер сам.
   - Если открыта — не трогает и пишет в сообщении, что перезапустить после партии: `pipeline.py serve --restart`.
8. **Таблица карт.** Если в `dev` поменялся `tools/cards-sheet/VbaCards.gs`, скрипт заливает его в Google Таблицу `Cards Config` через `clasp`. Сбой заливки доставку не останавливает. Script ID таблицы — в `.git/vba-pipeline/cards-sheet.json`, вручную — `pipeline.py sheet-push [--script-id ID]`. Подробно — `tools/cards-sheet/README.md`.
   - Обратный путь: «Отправить в игру» в таблице — коммит в `dev` без доставки. Его в основную папку раз в минуту подтягивает `pipeline.py follow`. Он работает вместе с сервером :5173: его запускает `serve`, и останавливается он вместе с сервером. `follow` берёт только `dev`, сдвинутый в одних файлах карт и баланса (`CARD_FILES`), и не трогает откаченную основную папку и идущую доставку.

Проверка (шаг 3) при правке `src/cards.config.js`, `src/game.config.js`, `src/game.js` или CSV таблицы ещё сверяет `cards-google-sheet.csv` и `balance-google-sheet.csv` с кодом (`node tools/cards-sheet/cards-csv.mjs --check`).

Параметры:

- `--message "<заголовок>"` — обязателен, если в ветке несколько коммитов.
- `--dry-run` — сжатие, версия, проверка и пробы, без заливки.
- `--no-app` — только `tools/`, `docs/`, `tests/` и прочее вне игры: без версии, проверки и пробы. Игровые пути — `src/`, `assets/`, `styles/`, `index.html`, `controller.html`, `styles.css`, `server.js`, `cards-google-sheet.csv`, `balance-google-sheet.csv`. Если они есть в изменении, скрипт откажет.
- `--attempts` (по умолчанию 4), `--lock-timeout` (30 мин), `--queue-timeout` (60 мин).

После доставки скрипт печатает «Доставлено…». Исполнитель **сам** отправляет его PM и владельцам задетых зон. Адреса: `python3 tools/pipeline.py chats`. Записи ведёт PM: `chats --set "<чат>" <local_…id> --zone "<зона>"`.

## Пробы

`tools/probe.py` — одна команда, последняя строка `PASS …` или `FAIL …`. Полный вывод лежит в папке `--out`.

| Что | Команда |
|---|---|
| Поведение | `python3 tools/probe.py test tests/<файл> [--out Logs/probes/{run}]` |
| Экран ПК | `python3 tools/probe.py shot --out Logs/probes/{run} [--path "/?…"] [--eval "<js>"]… [--size 1600x900]` |
| Экран пульта | `python3 tools/probe.py shot --out Logs/probes/{run} --path "/controller.html?…" --size 390x844 --mobile` |

`shot` поднимает `server.js` этой папки на её собственном порту (5174 + хэш имени папки, никогда не 5173) и снимает кадр Chrome без окна (`tools/shot.mjs`). Затем гасит сервер. Как устроен снимок:

- временный профиль, звук выключен;
- ждёт сигнала готовности: `document.documentElement.dataset.vbaReady === '1'`, когда игра его ставит, иначе загруженной страницы, шрифтов и двух кадров;
- `--eval` выполняет шаги и ждёт их промисы;
- запросы в Google Таблицы, `/api/game-history` и `/api/autoplay-runs` блокируются;
- непойманная ошибка страницы — это FAIL; `--allow-errors` в `shot.mjs` разрешает их;
- таймаут повторяется один раз.

Пульты-телефоны в пробах — это node-клиенты по HTTP, а не браузеры. Каждая проба пишется в журнал `.git/vba-pipeline/activity.jsonl` (`tools/activity.py`). `deliver` добавляет в своё сообщение строку «Проверки до доставки: …».

## Бот-партии для баланса

`python3 tools/probe.py autoplay` играет встроенным автопрогоном («Авто») партии ботов без окна (`tools/autoplay.mjs`) и пишет сводку: длина партии, шаги за ход, бои и возвраты на старт, откуда приходят монеты, финал и очки. Это не проба доставки, а замер правил (обзор настольной игры, 12 октября 2026).

```bash
python3 tools/probe.py autoplay --players 2,3,4 --games 20 --out Logs/probes/{run}
```

- Последняя строка — `PASS autoplay …` с цифрами по каждому числу игроков или `FAIL …`. Полная сводка — `summary.txt`, сырые ходы и бои — `p<N>.json` в папке `--out`. Запуск пишется в журнал проверок.
- У каждого числа игроков свой сервер на свободном порту системы, не :5173 и не порт папки (его занимает `shot`). `/api/*`, включая `/api/autoplay-runs`, отвечает он сам и никуда не пересылает. Google заблокирован, в Таблицы прогон не пишет.
- Числа игроков идут параллельно, Chrome на низком приоритете. 20 партий — ~3 мин на двоих, ~8 мин на четверых.
- `--seed N` — те же код и сид повторяют те же партии. Без него сид случайный и печатается.
- `--variant файл.mjs` — попробовать правило, не трогая код: `export default { 'src/game.js': (src) => src.replace('…', '…') }`.
- `--set "<js>"` — выставить настройку на странице до старта.
- `node tools/autoplay.mjs report <папка>/p3.json` — пересобрать сводку.
- Хуки статистики вставляются в копию `game.js` по якорям. Сдвинулся якорь — прогон и тест `tests/tabletop-rules.test.cjs` назовут его.

## Основная папка и сервер

- `python3 tools/pipeline.py serve` — запустить игру пользователя на :5173 из основной папки. `--restart` перезапускает, `--stop` останавливает. Лог: `.git/vba-pipeline/server.log`.
- `python3 tools/pipeline.py sync-main` — подтянуть основную папку вручную, а также вернуть её после `rollback`.
- `python3 tools/pipeline.py rollback [--to <commit>]` — основная папка откатывается на предыдущую доставку (detached HEAD), `dev` не меняется. Обратно — `sync-main` или следующая доставка.
- `python3 tools/pipeline.py status` показывает, где ты, отставание от `dev`, неопубликованное в `main`, очередь, установленную версию, сервер :5173 и все папки.

## Чистка диска

Правила пользователя из The Village (11 октября 2026), здесь — по «да» пользователя 23 октября 2026. `deliver` раз в 6 часов запускает `tools/cleanup_disk.py --apply`. Вручную: `python3 tools/cleanup_disk.py` — предпросмотр, `--apply` — удалить.

- **Папки чатов** удаляются, если они чистые (нет правок и новых файлов), HEAD не двигался и ни один файл не менялся 3 дня, а чат не занят задачей на доске. Ветка остаётся, `pipeline.py new <имя>` ставит папку обратно на неё.
- **Пробы** `Logs/probes/*` старше недели удаляются во всех папках.
- **Не трогает никогда** основную папку (`dev`, игра пользователя), хранилище git и папку, из которой запущена.
- Бэкапы сборок, как в The Village, нам не нужны: бэкап доставки — прошлый коммит (`pipeline.py rollback`).

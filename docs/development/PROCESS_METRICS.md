# Метрики процесса

Что мы меняем в работе чатов и пайплайне и чем проверять, помогло ли это. Процесс и метрики перенесены из The Village 11 октября 2026. До этого проект вёлся Codex-чатами, их журналы не сравниваются.

## Источники

Всё лежит локально, ничего не уходит с Mac.

| Источник | Что в нём |
|---|---|
| `.git/vba-pipeline/deliveries.jsonl` | каждая доставка: время проверок, проб и всей доставки, попытки, ожидание очереди, проверки до доставки (`work`) |
| `.git/vba-pipeline/activity.jsonl` | каждая проба по папкам, длительность, успех (`tools/activity.py`) |
| `.git/vba-pipeline/effort.jsonl` | какой уровень размышлений PM поставил чату перед задачей (`pipeline.py effort`) |
| Переписка чатов `~/.claude/projects/-Users-qooobooo-Game-Dev-Very-Big-Adventure*/*.jsonl` | вызовы, контекст, токены, виды действий, задачи — `python3 tools/work_profile.py --since <дата>` |
| `get_usage` в PM | лимиты плана (5 часов, неделя) и заполненность контекста чатов |
| `git log origin/dev` | доставки по дням и чатам, повторные исправления |

## Ежедневный отчёт

Решение пользователя, 11 октября 2026: каждый день — короткий отчёт (скил `vba-process-report`). Семь метрик из The Village, без Codex:

1. бюджет плана;
2. цена задачи по чатам;
3. доля PM;
4. контекст и сжатия;
5. проверки;
6. уровень размышлений;
7. скорость доставки.

- Команда: `python3 tools/process_report.py [--day ГГГГ-ММ-ДД] [--usage-week %] [--usage-5h-peak %] [--json]`. День по умолчанию — вчера. Работает несколько секунд, только по локальным журналам.
- Строка дня пишется в `.git/vba-pipeline/metrics.jsonl`. Повторный запуск за тот же день её заменяет, оттуда же берётся прошлый день.
- Лимиты плана скрипт сам не видит: PM берёт их из `get_usage` и передаёт флагами.
- Задача — от сообщения чату до её доставки. Минуты активные: паузы дольше 30 мин не считаются. Повтор — доставка той же задачи или её продолжения из той же папки за сутки.

## Срез «до/после»

- Токены и виды действий: `python3 tools/work_profile.py --since <дата>`.
- Доставки: поля `total_s`, `build_s` (это `node --check`), `probe_s`, `queue_wait_s`, `redone`, `work` в `deliveries.jsonl`.
- Сравнивать задачи одного типа: мелкие правки и большие системы сильно различаются по цене.
- Новое изменение процесса — строка в таблицу выше: метрика и исходное значение.
